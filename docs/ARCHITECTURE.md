# 架构与边界

机器人由通用编排内核和八类自动扫描插件组成：API、决策 Provider、typed 决策评估器、决策策略、标的发现
策略、研究工具、Agent 行为风控、业务风控。后两类是系统里**仅有的**风控插件；typed evaluator 只在
发现阶段可独立粗筛候选和判断是否继续扫描；若实例支持通用结构化问答，也可作为 Agent 按需调用的
`EVALUATE_FACTS` 工具，仅对已提供事实做有界分类或评分，不替 Agent 做交易决策、提案复核、风控或执行。
插件系统只负责目录发现、启用顺序、JSON schema 验证、配置回调调用、生命周期和可选的统一网络代理解析，
不包含平台名、凭证、URL、平台专属代理、资金数字、损益公式或策略内容。

## 源码布局

- `core/`：通用运行配置、领域模型、账户状态持久化与过滤协议（规则协调器、判定结果）。
- `plugin_system/`：插件契约、自动发现、生命周期、启用状态和配置回调。
- `agent/`：Provider 决策协议、typed evaluator 通用协议、多步研究工具协议和文本策略协议。
- `runtime/`：启动装配、通用业务事件循环、市场评估、动作执行、SQLite、报告、Passkey/ECDH 与 Web 界面。
- `plugins/`：按 `api`、`providers`、`evaluators`、`strategies`、`market_discovery`、`research`、
  `agent_policy`、`risk` 八类组织的内置插件。

Binance 与 Polymarket 的配置、读取和写入实现分别位于 `plugins/api/_binance/` 和
`plugins/api/_polymarket/`；插件系统不引用这些平台目录。

## 运行与触发模型

后台业务的起点在各 API 平台插件，而不在一个通用定时器中。已启用平台完成私有配置并且未暂停时，
通用运行主管调用该插件返回的 runtime `start` 回调；Binance/Polymarket 随即启动各自的事件线程。扫描
间隔、分页大小和失败退避来自该平台原有的私有 JSON schema。旧的每轮 10 个主题、6 个决策字段已移除；
业务流程不再把它们当作停止条件。

平台线程到点后不自己决定读什么。它调用框架注入的 `discover_markets` 回调，由通用发现引擎决定本轮宽扫
多深、调用哪些读接口、把哪些标的交给业务流程；平台插件只保留“什么时候扫”。回调和 `submit_scan`
一样走同一条业务事件队列，所以发现与决策不会互相穿插，SQLite 也始终只被
一个线程写。随后平台线程把返回的标准化主题通过 `PlatformScanEvent` 提交给队列并等待处理结果。
通用队列串行消费事件，避免两次 Agent/账户写流程互相穿插。事件处理过程中，研究工具可基于业务需要
主动调用当前或其他已就绪 API 插件的详情、盘口、K 线和跨市场搜索；执行阶段也由通用框架主动调用事件
所属平台的写接口。因此“定时扫描归平台、业务编排归通用框架”，并不把研究或下单逻辑塞进平台定时器。

`once` 是显式主动扫描入口：通用框架直接调用每个平台 API 一次，然后复用相同业务处理流程；它不创建
周期。暂停、禁用、配置变为不完整、刷新、插件消失或程序退出时，runtime `stop` 与插件 `teardown`
都会被调用并等待线程退出。

## 标的发现与策略进化

发现和决策两条链路结构相同：内置策略 + 可选用户插件 + 由实测结果生成的叠加层。

- **内置策略**是框架不变量，没有配置面，不出现在插件中心的可编辑卡片里；当前全文可以导出查看。
- **叠加层**是先验权重和教训条款，由运行时自己的已完成决策测出来。教训文本由统计模板生成，不由模型
  撰写，所以每一句都能追回到桶名和样本数。样本不足或偏离消失的条款自动淘汰。
- **用户插件**的原文永不被改写。进化只是可随时关闭的附加层；关闭后模型看到的就只有用户自己写的文本。
- 测量始终运行，与当前由谁发现或决策无关，所以切回内置策略时它不是旧的。
- 硬闸（成本、结算风险、不可交易的临近截止时间、关闭状态）写在内置内核里，任何学到的条款都不能
  放松；偏好的揭标天数不是硬上限。

发现层只把真实 FILLED/MATCHED/PARTIALLY_FILLED 的 BUY/SELL 计作有效活动，并在赎回/结算后单独累计可观测
成本后的净收益；提案、无仓卖出、风控拒绝和失败订单都不是活动，未知收益不填成零。决策层测的是校准度——
声明 70% 的那些标的实际赢了几次；后者只在插件能可靠判定结算赢家的平台上累积。注入提示词的教训条数和测量桶数都有上限，完整表通过
`RECALL_MEASUREMENTS` 工具和策略导出获取，不常驻上下文。

发现不是固定数量流水线。框架在页数、时限、调用次数和取消等硬资源边界内逐页读取；启用的 typed evaluator
就候选质量与边际价值返回 Choice/Score/Noul。高置信且自洽的继续状态可省掉逐页 LLM 调用；其余情况交给
LLM 复核。粗筛把高置信 DEFER/REJECT 从最终输入中移除，但按候选规模平方根保留质量抽样，不能筛空候选池。
置信阈值以 0.90 起步，用这些抽样的后续真实有效活动校准：发现漏判时提高，稳定无漏判时逐步下降，硬下界
为 0.80。暂停或撞到资源边界会持久化每个来源的分页游标。evaluator 不可用或任一评估器报错时不做候选
剔除，扫描仍受同一资源边界保护，不回退到旧业务配额。

## 一次决策的数据流

1. 平台 runtime 到点调用框架的发现回调；typed evaluator 先做可选粗筛，Agent 从压缩后的 frontier 选出
   本轮名单并把精确 `discovery_selection_id` 落库；质量抽样和动态阈值避免粗筛变成最终裁决。
2. 策略插件按自己的状态、outcome 和流动性配置选择候选；跨 Topic round-robin 展开 outcome，避免第一个
   多市场 Topic 独占尝试；盘口读取失败不计作已开始的决策。
3. 内核组合当前市场、持仓、API 能力、风险清单和策略文本，并给出统一账本、双方 CLI 私有历史路径、
   当前轮次与应续接轮次 ID；不自动拼历史窗口或替 CLI 摘要。
4. Provider 按有序列表创建一个新的官方 CLI 会话；同一轮的业务工具往返续接该会话。研究工具插件动态
   贡献预测市场专用工具名、说明和执行器。
5. Agent 用官方 CLI 自带的搜索、网页、文件、命令、skills/插件收集通用证据，并可调用框架注入的跨市场、
   行情或业务历史工具，再生成结构化提案；evaluator 不进入这条交易
   决策链，提案直接交给既有风控。
6. 规则协调器按目标把动作交给链上每个已启用插件：可以允许、缩减、拒绝或停止；任意一个拒绝或抛异常
   就整体失败，且链上后面的插件不再执行。没有适用插件时内核不额外增加政策。
7. 执行网关调用当前运行模式的写传输：实盘使用 API 插件线上传输；显式开启纸面交易时，只把最终写动作
   交给本地纸面传输，真实读取、报价、过滤和结算判断保持不变。
8. SQLite 决策台账关联上下文、证据、提案、风控、执行和后续观察。

管理 Web 服务不以“配置不全”作为进程启动失败条件。它先使用已经确定的 SQLite 路径提供 Passkey、配置和
审计界面；运行主管只判断是否有可用 Provider，并调用各平台的 readiness/runtime。至少一个平台 runtime
成功启动才算机器人正常运行；策略、研究和两类过滤插件不作为主链硬依赖。单个平台不可用或暂停时只停止
该平台。配置经界面保存后即时重建并重新评估。

`SEARCH_MARKETS` 只提供候选。不同平台是否描述同一事件、能否共享外部证据、结算条件是否一致，均由
Agent 根据各 API 插件的原始规则和能力清单判断；内核不以标题相似度替代语义决策。

## 平台差异

通用写接口使用标准化计价金额/份额字符串，不包含链上精度。Binance 插件内部转换其接口单位并签名；
Polymarket 插件内部处理 pUSD 精度、CLOB 凭证、钱包签名和 Relayer。平台原始订单状态也由对应插件
归一化，通用网关只接受标准状态。API 能力清单只声明真实实现的
功能；无法可靠确定结算赢家的插件必须把 `settlement_status` 声明为 false，而不是返回猜测。当前
Polymarket 适配器只有在 outcome 价格离开交易区间并达到结算阈值时才返回胜负，开放市场不会按领先方猜测。

充值和提现也遵守同一边界。通用资金契约只表达可用余额、目标余额请求及请求状态；Polymarket 插件自己
调用官方 Bridge，实时解析支持资产、生成账户充值/提现地址、验证精确合约和处理状态。Web 的资金管理页
只渲染插件 notices，不包含 Polymarket URL、USDC 合约或 Bridge 请求格式。部分到账结清旧请求为一次
`partial` 回答，运行时用新行情和已有持仓重新询问决策逻辑；需要余款时由决策逻辑另建请求，框架不会把
部分到账提升为 `satisfied`。

本地 `AccountState` 是已确认响应的运行时镜像和风控输入，不是撮合器。只有远端成功响应后才更新；开放
限价单不会因本地盘口穿价而被自行标记成交。

已接受的成交、结算和充提同时写入追加式 `pnl_events`。平台、实盘/纸面和币种分别核算，充提只改变
外部资金流；缺少成本、盘口标记时间或升级前逐笔历史时保持未知/不完整，不能用零填充，也不能把卖出
收入直接当利润。事件账本写入失败不会伪装成远端动作失败或尝试回滚已经接受的动作，而是留下高优先级日志。

纸面交易是明确例外：`PaperMarketApi` 包装平台插件，随后按插件返回的报价及固定费率立即在本地
记为完全成交。它不模拟排队、部分成交或额外滑点，结果始终标记 simulated，并使用与实盘分离的状态文件。
Polymarket 的本地 quote 不是成交保证，价格相关的实际 taker 费尚未完整反映到内部账本；因此纸面净收益
不可代替实盘对账，详见[选标与成本复核](MARKET_SELECTION_REVIEW.md)。
包装位于业务风控之前，因此两类过滤插件看到的调用与实盘相同。

## 会话边界

Codex 和 Claude 客户端维护自己的登录、官方 Agent 能力和私有会话记录。每个顶层任务新建会话，同一轮
续接，下一轮重开。跨轮业务记录统一存入 SQLite；新会话同时获知 SQLite、从双方 AUTH_DIRECTORY 配置
解析出的 Codex 私有 sessions/索引与 Claude 私有 projects/sessions/history 路径，所以 Provider 故障转移后
可由新 CLI 自己读取双方历史。OpenRouter 也使用所选 CLI 的同一私有 HOME。框架只主动指出
当前轮次、最相关上一轮和显式续接轮次 ID，不替 CLI 选择、摘要或裁切内容。子进程只继承运行所需的
OS/客户端环境，不继承其他插件的私有配置。

管理会话与 Agent 业务记忆相互独立：`auth_db` 保存 admin Passkey、公钥签名计数观测值（仅诊断）、挑战、ECDH 会话和
防重放 nonce；`session_db` 保存 Agent 输入输出和决策台账。两条数据库路径先由应用配置解析，再初始化
任何持久层。登录后的业务数据经统一加密分派端点进出，认证引导端点不暴露业务内容。
