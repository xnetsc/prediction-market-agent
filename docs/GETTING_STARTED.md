# 上手：从零到它开始做决策

这份文档是一条路径，不是功能清单：按顺序走完，机器人会真的开始看市场、写决策记录。每一步都写清楚
**做完之后你应该看到什么**，看不到就是这一步没成，不用继续往下走。

功能细节在各自的文档里，本文只在需要时指过去。

---

## 0. 需要准备什么

| | 为什么 |
|---|---|
| Docker | 机器人跑在容器里。启动脚本会检查并按需安装 |
| 一个 AI 模型服务 | 决策是模型做的。三选一即可：Codex 订阅、Claude 订阅、或 OpenRouter 的 Key |
| 一个交易平台账号 | 目前内置 Polymarket 和 Binance 插件 |
| （可选）有显卡的机器 | 跑本地粗筛模型，省钱。见第 6 步 |

不需要装 Python、不需要建虚拟环境、不需要自己构建镜像。

---

## 1. 启动

```bash
git clone https://github.com/xnetsc/prediction-market-agent.git
cd prediction-market-agent
./start-local.sh          # Windows：.\start-local.ps1
```

脚本会拉取镜像、创建容器、等健康检查通过。数据落在仓库里的 `runtime-data/`，升级镜像不会动它。

**应该看到**：终端最后打印出 `http://127.0.0.1:8765`，浏览器打开是「运行概览」，上面写着还缺什么。

此时机器人**还不会交易**——它在等你把模型和平台配好。

---

## 2. 接一个 AI 模型服务

进「模型服务」页。三条路，配好任意一条就能跑，配多条会按实测质量轮换，某一条限流或掉线时自动切换。

- **Codex / Claude**：点登录，按向导走。用的是你的订阅额度，不额外计费。
- **OpenRouter**：填 Key 和模型。按 token 计费，模型列表只显示支持结构化输出的那些——不支持的填了也没用，决策要求模型按固定格式回答。

**应该看到**：卡片上出现账号状态和额度窗口（比如 `5 小时窗口 已用 12%`）。显示「额度用完」时会告诉你什么时候恢复，机器人会自己等，不会空转。

细节：[客户端账号说明](CLIENT_ACCOUNTS.md)

---

## 3. 接一个交易平台

进「插件中心」，启用 Polymarket 或 Binance，填配置。

Polymarket 只需要一个钱包私钥——地址、钱包类型、CLOB 凭据都是从私钥推出来的，配置表单里那几个空格留空就行，不是缺失。没有钱包的话，「钱包」面板里有生成按钮，生成的是空钱包，要你自己往里转钱。

**应该看到**：平台卡片从「待配置」变成「已连接」，「资金管理」页能读出余额。

细节：[市场 API 插件](API_PLUGINS.md)

---

## 4. 入金

进「资金管理」页，点「我要充值」。界面会告诉你：哪条链、哪个地址、转什么币——**这三样错一样，钱就找不回来**，所以不要凭印象转。

转完把交易号填进去点确认，它会去链上查，到账了会说到账，查不到会说查不到。

充值时可以写**附言**，比如「这 25U 三天内用完，只买体育」。这不是备注：机器人会读懂它，之后每一轮决策都照做，做到哪一步写在总览页的「转账附言与要求」里，你随时可以删掉某条，删了就不再影响决策。

**应该看到**：余额变了，总览页出现你写的那条要求。

---

## 5. 让它跑起来

回「运行概览」，取消「暂停全部平台」，保存。

**应该看到**：平台状态变成「运行中」。等一轮扫描结束（默认最短 60 秒一轮，实际间隔由 AI 自己决定），「决策账本」页出现记录。

账本上一条记录 = 一次判断，**不等于一笔成交**。点开先看四项：发现了什么、怎么分析的、结论、结果。多数结论会是「观望」——预测市场的多数标的定价本来就大致正确，说它没机会是对的答案；有机会才是少数。

细节：[Web 管理界面](WEB_UI.md)、[决策账本](CONSOLE_AND_LEDGER.md)

## 6.（可选，省钱）本地粗筛模型

每轮要从几百个候选里挑，这一步交给昂贵模型既慢又费。本地决策模型专做判断题——该不该看、是不是重复上架的同一个问题、上次说的触发条件发生了没有——**不花钱**，也不会因为"想多了"编出理由。

它需要 GPU，而 macOS 上的 Docker 不把显卡透传给容器，所以它**跑在你的宿主机上**，机器人通过网络调它。

进「模型服务」页最下面的「本地决策模型」，下载资源包，然后一条命令：

```bash
unzip laya-service.zip && bash laya-service/start.sh
```

首次启动会自动装一个无头浏览器、下载约 800MB 模型并留在本地，之后每次启动都从本地读。

**应该看到**：终端出现 `laya ready: convaiinnovations/laya on webgpu`。**`on webgpu` 这几个字很重要**——如果是 `on cpu`，说明没拿到显卡，它还能答但慢到不可用。然后回界面点「测试连接」，显示「跑在 GPU 上」才算好。

## 7. 日常怎么看

| 你想知道 | 去哪看 |
|---|---|
| 它为什么这么做 | 决策账本，点开任意一条 |
| 赚了还是亏了 | 盈亏账本：已实现/未实现、手续费、净入金分开算，成本不全的会标「未知」而不是当成利润 |
| 它现在能不能干活 | 运行概览：模型额度、平台状态、暂停原因 |
| 出过什么毛病 | 决策账本底部「采集与分析异常」，读完可以清掉 |

命令行（可选）：

```bash
docker compose exec robot prediction-market-agent doctor           # 自检
docker compose exec robot prediction-market-agent report --since-hours 12
docker compose logs -f robot
```

## 出问题时

| 现象 | 多半是 |
|---|---|
| 账本一直没有新记录 | 机器人被暂停了，或三个模型服务都没额度——运行概览会写明是哪种 |
| 页面点了没反应 / 一直转 | 刷新一次；页面顶部若有「控制台有更新」提示，点它 |
| 平台显示「未就绪」 | 卡片上会列出缺哪个字段，点进去补 |
| 本地模型显示 `on cpu` | 那台机器没拿到显卡：确认服务跑在宿主机而不是容器里 |

更深的排查：[集成测试](INTEGRATION_TESTS.md)、[环境诊断](ENVIRONMENT.md)、[部署](DEPLOYMENT.md)

## 它不做什么

- 不替你保证盈利，也没有内置止损止盈——阈值由决策策略文本或业务风控插件决定，框架不替它们判断；
- 不在余额不足时改判断：该买就报买，平台拒单会如实记在结果里；
- 不用公式代替模型决定选哪些标的：模型不可用时**一个都不选**，并记一条异常说明原因。
