# Web 管理控制台

入口为部署的管理地址。桌面左侧固定导航，800px 及以下使用左上角菜单；手机和平板不要求安装应用。
页面不因屏幕尺寸、User-Agent 或是否有触摸屏而跳过认证。公网必须使用 HTTPS、Passkey 和已有加密会话。

## 分区与操作

| 分区 | 内容与例子 |
| --- | --- |
| 运行概览 `#overview` | 权益与活动指标、全局/各平台运行状态；勾选暂停并保存 |
| 决策账本 `#decisions` | 独立显示市场采集、逐市场粗筛队列覆盖量、候选与降级异常；可只暂停/恢复粗筛轮询，定时复查继续；再看建议/最终动作、中文状态和原因，技术原始记录默认收起 |
| 盈亏账本 `#pnl` | 按平台、实盘/纸面和币种分列总盈亏、已实现/浮动盈亏、权益、手续费、净入金、开放仓位和逐笔事件 |
| 资金管理 `#funds` | 按平台查看真实可用余额、待处理资金请求、精确充值路线与状态，以及绑定网络/币种的转出操作 |
| 模型服务 `#models` | 服务可用性与实测质量表（状态、退避剩余、成功率、校准 Brier、他评、质量权重），质量优先/强制设置顺序开关，以及启用、顺序、账号登录与凭据导出/导入、OpenRouter、模型、代理配置与扩展安装 |
| 插件中心 `#plugins` | 除模型服务外的七类入口；每类是二级页面，含用途、流程、操作提示、有序启用名单及配置 |
| 程序设置 `#settings` | 通用运行参数、数据库位置、扫描目录、运行清单；保存后需重启的字段有说明 |
| 安全与会话 `#security` | 添加/重命名/删除 Passkey、查看登录设备和踢出会话；最后一个 Passkey 不允许删除 |

### 资金管理与决策资金请求

资金操作从交易平台的配置卡片中分离到独立“资金管理”页，但协议仍属于平台插件。通用页面只读取插件的
资金 notices 并渲染字段，不知道某个平台使用账户内划转还是链上 Bridge。钱包查看/备份、充值与转出是
随时可用的操作，集中列在资金页的“可用操作”，不计入顶部“待处理”数量；只有真实存在的资金补足请求或
插件错误才会上浮提醒。平台配置页保留私钥、凭据、端点和网络代理等连接字段，不重复显示充值/提现表单。

同一页和顶部提醒对插件状态的并发读取会复用一份进行中的请求，避免把首次连接的多次远端查询重复执行。
Polymarket 暂停态也保留一个由插件生命周期管理的只读实例，不会为余额、钱包、充值和转出分别重建 SDK。
已有账户先派生 CLOB 凭据、仅在新钱包没有凭据时创建；钱包类型解析与凭据派生并行，客户端就绪后余额、
RPC、Bridge 路线和钱包信息继续并行读取。实际容器冷启动资金接口约 11.7 秒，随后刷新约 0.3 秒；界面在
等待期间明确显示正在读取，配置刷新或插件 teardown 会关闭并重建这些连接与短期缓存。“刷新资金状态”
会强制重新读取页面数据，但仍复用有效期内的底层连接。

Polymarket 充值区实时列出完整资产名称、缩写、网络、chain id、合约和最低金额，并显示该账户的 Bridge
充值地址；交易号提交后依次核对源链和 Bridge 状态。转出区先显示真实可用 pUSD，再用一个不可拆分的下拉
项绑定目标网络与代币合约，另填金额和交易所/钱包接收地址。这样不会出现“选了 A 链却填了 B 链合约”的
组合。

决策逻辑仍通过 `ACCOUNT_FUNDS`、`ENSURE_FUNDS`、`FUNDING_STATUS` 与 Provider 交互。资金页上的到账
确认会更新同一份请求记录：未增加可用余额时继续等待；达到目标时完成；部分到账时只唤醒决策一次，让它
选择继续、不执行并等待补足，或先建立分阶段仓位同时继续补足。第三种余款到账后仍按新行情与已有持仓
重判，不自动补单。

### 登录凭据导出与导入

Codex 和 Claude 的卡片上各有“导出登录凭据 / 导入登录凭据”。导出下载一个只含登录态文件的 JSON，导入
用它覆盖当前登录状态，用于换部署时免去重复登录。导出文件含可直接使用的令牌，确认框会明确提示；未登录
时导出不可用，属于其它客户端的文件导入会被拒绝。

### 策略进化与导出

“标的发现策略”和“决策策略”两个二级页顶部各有一块策略面板：

- 一个开关控制**你自己的**策略插件是否附加运行时学到的内容，默认开启。关闭后你的插件只用你写的原文，
  策略文件任何时候都不会被框架改写。
- “导出当前生效全文”按钮返回此刻真正发给模型的完整文本：内置内核、当前先验权重及其样本数、生效的
  教训条款，以及一个含全部教训和完整测量表的 JSON 下载。
- 内置策略不作为可编辑卡片出现，也没有配置字段，但它的全文和进化状态同样可以导出。你使用自己的插件
  期间，内置策略仍在被测量，导出里会单独列出它的当前状态。

### 机器人为什么没运行？

“运行概览”顶部直接显示未运行、已暂停、部分平台运行、正常运行或“仅启动管理界面”。未运行时自动
展开启动向导，并分成两个互斥 Tab，不再把两类事项上下混排：

- **启动必需**：至少一种可用模型服务 → 至少一个可启动平台。顶部待处理数量只统计这里。
- **可选增强**：当前选用的策略、研究和两类过滤插件。未就绪数量单独显示，不阻止机器人启动。

默认显示“启动必需”；切换 Tab 只改变展示，不保存配置、刷新插件或触发机器人动作。每项只展示插件
自己的 readiness 或 runtime 报告和“打开插件”入口；通用程序不读取字段 schema 来推断缺少哪种 Key。

例如：Binance 缺少必要字段时，在向导点击“配置 binance”，填写提示字段并保存，再回概览检查状态。
不使用该平台时可关闭其插件。普通启动下，配置齐全且未暂停会自动运行；启动参数修改需要按页面提示
重启。测试代码可显式创建不启动运行进程的界面验收实例，此时页面标为“测试实例”并说明这不是配置问题；
正式 CLI、Compose 和云容器入口均使用正常机器人入口，不能把测试实例当作正式部署状态。
“已满足”表示插件报告可启动；机器人只有在至少一个平台 runtime 实际进入运行状态后才显示“正在运行”。

暂停不是配置完整性条件，所以不出现在启动必需清单。用户主动暂停时，暂停选择先持久化，页面刷新后仍按
已保存的选择勾选；新的业务事件立即停止进入队列。若上一轮模型调用尚未结束，顶部显示“暂停已保存，正在
结束旧任务”，不能把仍在执行的调用误报为已停止。该调用结束后显示“机器人已暂停”；手动点击“重新检查”
可读取最新状态。正常入口下，保存模型/平台配置、插件启用状态或取消暂停后会在后台重新检查并启动已就绪平台，
无需重启或再点“启动”。

### 选择 Codex / Claude 模型与推理强度

每次打开模型配置页，都会调用插件读取函数回填当前已保存值，不需要手动点击加载。
若本页有未保存修改，则保留这些草稿并显示提示；其他字段仍读取服务器当前值。密钥只显示“已保存”
提示，不返回明文。加载失败会明确报错并保留原输入，模型目录返回也不会清空或改选当前模型。

打开“模型服务 → 配置模型”，模型和推理强度均为下拉列表，展开表单时自动读取当前客户端。选择模型后，
强度列表按该模型重新获取，并恢复为默认待你选择；不会把上一模型不支持的强度直接套给新模型。
低、中、高、极高等中文名称保留原始参数值。留空表示使用客户端默认，读取失败会说明原因并保留当前
配置，不伪造可用模型；客户端未声明强度时仅提供默认项。高强度通常增加时延和消耗，不保证结果更好。

列表在插件内缓存最多一分钟，可以点击刷新重新读取；保存/刷新插件后重新初始化缓存。模型权限仍以
服务商实际响应为准。示例：选择某模型后从列表选择“高（high）”，点击保存配置；实际调用时会传入对应
客户端参数。两个客户端各自保存 `CODEX_EFFORT` / `CLAUDE_EFFORT`，OpenRouter 配置不受影响。
Codex、Claude 的候选分别来自各自登录客户端，不按 OpenRouter 的 schema 能力筛选；Codex 连客户端
标记为隐藏的原始模型条目也返回，个别内部用途条目是否能用于交易决策仍以调用结果为准。OpenRouter 的候选来自 OpenRouter。OpenRouter 使用
Codex CLI 作为 Agent 时采用独立的客户端缓存目录，仍可读取 Codex 账号配置与技能，不会把 OpenRouter
模型写入官方 Codex 的模型目录。
配置保存先持久化，再在后台切换运行实例，不等待正在进行的模型调用结束；页面会明确显示已保存但
运行条件仍在更新，刷新后不会丢失设置。
客户端版本更新默认先后台下载并验证；“升级客户端”只有新版准备好时才能点击，确认后立即切换。
下载失败会显示失败状态并保留旧版，可再次检查重试；版本目录只保留新版和上一个可用旧版。

Codex、Claude 与 OpenRouter 的配置顶部统一显示“模型、凭据与网络连接”。Codex/Claude 各自的
`CODEX_HTTP_PROXY` / `CLAUDE_HTTP_PROXY` 在这个首要分区直接显示：默认 `INHERIT`，可改为
`DIRECT` 或该客户端专用代理。客户端目录、登录回调和升级周期放在折叠的高级设置中。
账号区分别列出服务端实际返回的短时与周额度窗口、使用百分比、重置时间和数据时间；计划没有某个窗口时
不会显示占位窗口。Claude 额度服务暂时限流时显示 Claude Code 最近一次成功缓存，并明确标注，不用订阅
计费提示代替额度结果。

### 连接 OpenRouter

1. 打开“模型服务”，找到 OpenRouter，点击“配置 OpenRouter”。若插件未启用，先勾选启用并保存；禁用
   插件不会为了展示配置而被初始化。
2. 填写 Key，并从自动加载的模型下拉框选择模型。目录请求使用
   `/models?supported_parameters=structured_outputs`，只保留同时声明 `tools` 与 `structured_outputs` 的
   型号；Codex 和 Claude 路径使用同一选择范围。不能手填未声明支持的 ID。Web Search/Fetch 等 CLI 特有
   声明由 OpenRouter 插件按“原生优先、缺失才兼容”处理，不以此隐藏模型。实际推理仍会强制具体供应端点
   接受 schema 参数，不会在失败时自动换用其他模型。
   OpenRouter 服务卡片直接提供 Agent CLI 下拉框和“保存 Agent CLI”按钮：`AUTO` 优先当前可用的 Codex，
   否则用 Claude；也可固定其中一个。专用配置页的主配置区也保留同一字段，不藏在高级设置中。卡片同时
   显示实际选中的 CLI 和当前检测到的可用 CLI；两个都不可用时 OpenRouter 不会显示为已就绪。
3. 修改 Key 或代理后保存，再刷新列表。目录声明不代表账号一定有权限或额度，因此实际调用错误仍会显示并
   进入 Provider 故障转移。
   Codex 的 Responses 请求仍携带原生 `text.format=json_schema`；考虑到部分 OpenRouter 兼容路由可能接收
   参数却返回带 Markdown 围栏的 JSON，插件还把完整 schema 明示在最终提示中。只允许纯 JSON 或单个
   JSON 围栏，剥离围栏后逐字段校验类型、必填、枚举、范围和额外字段；普通散文、夹杂解释或不合 schema
   的对象仍然失败，不会进入交易决策。
   模型服务卡片可点击“刷新余额与用量”：推理 Key 会返回本 Key 的消费与剩余额度；若还配置了可选的
   Management Key，会同时显示账户累计充值、累计消费和余额。查询沿用这一份插件的代理。
4. 用“启用”和“顺序”控制是否参与决策及回退优先级，点击“保存模型启用与顺序”。需要第二份 Key、模型
   或代理时，在同页填写 `openrouter_*` 名称并生成另一个插件文件；每个文件是一份独立 Provider 配置。

选择方式开关同时作用于已启用的决策 Provider 和发现阶段 evaluator：默认质量优先；选“强制按设置顺序”
时忽略质量。每类每次只尝试一个，失败后按当前模式回退；评估器可在插件中心分别启用 Jev 和 Laya。

深链接例：`https://robot.example/#model-config/openrouter`。Codex 模型设置对应
`#model-config/codex`，Claude 对应 `#model-config/claude`。模型服务不在插件中心重复展示；配置、启用、
顺序和安装扩展都在模型服务页完成，仍调用 Provider 插件提供的回调，不另建配置存储。
刷新插件或保存后重新加载配置会以服务器状态为准，其他未保存修改应先处理。

### API Key

每份 OpenRouter 插件必须配置一个推理 API Key，并通过 `Authorization: Bearer <API Key>` 用于模型目录、
推理请求和官方 `/key` 用量查询。可另填一个 Management Key，仅用于官方 `/credits` 账户余额查询；
OpenRouter 官方不允许用 Management Key 推理，程序也不会混用。两者都是秘密凭据，已保存值不回显。
插件私有透明守卫和账号查询固定连接 OpenRouter，不接受自定义端点；其他服务应由自己的 Provider 插件实现。

“程序设置”顶部单列统一网络代理。Codex、Claude、OpenRouter、Binance、Polymarket 和研究插件默认
`INHERIT`；每个插件自己的配置可覆盖为直连或独立代理。OpenRouter 透明守卫只对本机回环段使用 `NO_PROXY`，
守卫到远端的请求仍使用这份解析后的代理。守卫不翻译或吞掉 CLI 的工具协议。

API Key 输入关闭自动填充，并在支持字符遮罩的浏览器用遮罩搜索输入，减少密码框误识别；不支持遮罩
则保持密码输入，避免明文显示。浏览器/扩展可能忽略网站的自动填充设置，仍需在用户实际浏览器确认；
参考 [MDN 自动填充说明](https://developer.mozilla.org/en-US/docs/Web/Security/Practical_implementation_guides/Turning_off_form_autocompletion)。

### 插件分类二级页

| 地址 | 负责什么 | 用户需要做什么 |
| --- | --- | --- |
| `#plugins/api` | 读取市场、接收查询和订单 | 配置你使用的平台 |
| `#plugins/decision_evaluator` | 在发现阶段按类型协议低成本粗筛候选 | 选择并配置 evaluator；它不参与交易决策 |
| `#plugins/market_discovery` | 宽扫后选择本轮值得分析的标的 | 可使用内置策略，或启用自己的发现策略 |
| `#plugins/decision_strategy` | 指导如何分析 | 可选择一项策略，也可选择“不使用决策策略” |
| `#plugins/research_tool` | 为模型补充信息 | 按需启用和配置研究工具 |
| `#plugins/agent_policy` | 过滤 LLM 通过框架协议发起的业务工具 | 列出允许的业务工具和交易动作；CLI 自带工具由官方权限控制 |
| `#plugins/risk` | 过滤一切市场 API 动作（含只读） | 核对规则内容，不把启用等同于已有止损保障 |

插件中心每类显示简短流程和“你需要做什么”。Decision Provider 在底层仍遵循插件契约和自动扫描规则，
但只在“模型服务”呈现，避免两个重复入口。未启用插件只显示文件名和启用操作，不读取其说明或配置。
文件来源和错误细节默认收起；当前类别会带入下方插件安装表单。旧 `#plugin_类别_名称` 链接仍可跳转。

勾选启用、取消启用、修改顺序或切换策略时，当前卡片和右下角会先显示“尚未保存”；此时启动向导仍
反映服务器已保存状态。点击“保存启用与顺序”后，服务器先持久化选择，再后台协调运行中的插件；页面直接
显示已保存的插件状态，不等待尚未结束的采集或额外 runtime 读取。运行状态可手动刷新，
已禁用的过滤/研究/策略插件会从向导“可选增强”Tab 中移除。保存插件私有配置、删除配置、刷新
插件文件也会在当前卡片和右下角显示处理中、成功或失败，不再把结果只放在页面底部。

### 读懂一条决策

“决策记录”整块列表和“采集批次与候选记录”默认折叠，展开后每条记录仍可单独展开；
评估器粗筛、删除审计和诊断明细也默认折叠。粗筛暂停按钮不藏在列表里。
评估器粗筛明细合并后台持久队列的新结果与旧采集附带评估，按记录时间排序并标注两种时间来源。

每条记录对应一次判断，不保证发生交易。先看建议/最终动作与状态，再展开“查看决策过程”，依次查看
发现的市场、参考证据、模型判断、规则检查、执行与后续。没有最终动作时只标“建议”；规则拒绝、模型
失败、执行失败单独标识。平台返回的自定义状态保留原值，不猜测它是否成交；没有后续结果不声称盈利。
详细 JSON 和模型对话/工具/操作日志只在排查时展开。筛选最多显示最近 100 条匹配记录。

Codex/Claude 各自默认自动选择验证方式：手机/平板或非回环地址用设备码/验证码，桌面回环访问用本地回调。
卡片的“登录选项与客户端维护”和向导均可手动改为“本机网页回调”或“设备码 / 验证码”；
两客户端互不影响，不改变管理员 Passkey。已登录卡片以模型配置为主要操作，重登录、退出、检查和升级
放在折叠维护区；未等待登录时不显示无用的取消登录按钮。
向导切换会取消旧流程再启动，页面重载恢复自动。本地直接回调与助手方式
继续保留。流程、依赖和失败提示直接展示在向导中，详见 [客户端账号](CLIENT_ACCOUNTS.md)。

## 交互与适配

- 当前分区有标题和导航选中态，URL hash 支持刷新/前进/后退；每次进入分区自动读取一次，之后只由用户
  点击刷新，不做后台轮询。未显示分区保留在 DOM，不丢弃表单输入。
- 插件配置默认折叠；模型服务首页不堆叠所有表单，点击连接卡片才显示所选服务表单。
- 运行概览给出模型、平台、策略三个起步入口。暂停修改在保存前不会被状态刷新覆盖。
- 网络页面只展示选中连接，用中文解释直连或代理；NO_PROXY、内部标识、源端口等默认折叠。
- 程序参数、扫描目录、运行清单默认收起，按钮区分主要操作与删除/重置操作。
- 表格放在可键盘聚焦的独立滚动区域，不把整页撑宽；没有数据时显示空状态，不生成虚构图表或交易。
- 手机主要控件至少 44px 高；支持键盘焦点、跳过导航、减少动画偏好，登录弹窗内部可滚动。
- 使用本地 CSS/JS 与系统字体，不依赖外部 CDN。视觉资源随 wheel 和容器打包。

## 验收

`tests/dashboard_ui.cjs` 使用 Playwright 驱动本机 Chrome，在 390、768、1440px 检查八区导航、三种 Provider
常驻账号/额度信息、表单展开、
分类二级页、跨页未保存值、OpenRouter Key/受限模型字段、独立配置生成、启用顺序、独立采集证据、按需分页读取的评估器粗筛明细、盈亏账本、决策五步
说明、网络折叠、远程登录弹窗和 JavaScript 错误。保存/模型列表部分由浏览器本地拦截返回测试响应，
验证真实表单处理函数的载荷，但不把测试凭据或修改发送到运行部署。其他操作只读取管理服务，不执行
交易或账号授权。后端配置存储与模型列表另由 `tests/test_model_catalog.py` 等测试验证。
